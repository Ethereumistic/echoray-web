# Convex Authentication System Architecture

This document provides a comprehensive analysis of the Echoray authentication system using Convex Auth, covering implementation details, the two-step OTP verification flow, and integrated profile management.

---

## 1. Authentication Overview

Echoray uses **Convex Auth** (`@convex-dev/auth`) as the core authentication engine. We've implemented a custom **Two-Step OTP (One-Time Password)** flow for enhanced security and email verification.

### Key Technologies
- **Convex Auth**: Session management, user tables, and password hashing.
- **Resend**: Transactional email delivery via the `@convex-dev/resend` component.
- **Native Crypto**: Secure, non-sequential 6-digit OTP generation using the Web Crypto API.

---

## 2. Authentication Flows

All authentication actions are split into two steps to ensure email ownership and security.

### A. Sign Up Flow
1. **Registration**: User submits the Sign Up form (`src/components/auth/sign-up-form.tsx`).
2. **OTP Generation**: The system creates a user and triggers a verification email via `convex/ResendOTP.ts`.
3. **Verification**: User enters the **6-digit code**. The UI auto-submits upon typing the final digit using the `OTPInput` component.
4. **Completion**: Upon successful verification, the user is redirected to the dashboard.

### B. Sign In Flow (Unverified Support)
- **Standard Login**: Verified users log in normally with email/password.
- **Unverified Login**: If a user logs in but hasn't verified their email, they are automatically redirected to the OTP verification step securely, without needing to re-register.

### C. Password Reset Flow
1. **Request**: User enters their email in the Forgot Password form.
2. **OTP Email**: An 8-digit code (if configured, currently **6-digit** for consistency) is sent via the `ResendOTPPasswordReset` provider.
3. **Reset**: User enters the code along with their new password. The UI validates password matching and length before auto-submitting.

## 3. Email Infrastructure

### Configuration
- **Domain**: `mail.echoray.io`
- **Sender**: `Echoray <core@mail.echoray.io>`
- **Delivery**: Queued via `@convex-dev/resend` for high reliability.

### Security & Throttling
- **OTP Length**: 6 digits (Industry standard).
- **Expiration**: 
  - Verification Codes: **24 hours**.
  - Password Reset Codes: **10 minutes**.
- **Rate Limiting**: A **60-second cooldown** is enforced per email address to prevent spamming and Resend API abuse.

### Branding & Design
- **Consistent Visuals**: All emails use a **hardcoded dark theme** to prevent "flash of white" or color inversion in mobile email clients.
- **Colors**: 
  - Background: `#1a1b1e`
  - Card/Surface: `#222327`
  - Accent/Buttons: `#0066ff`
  - Text: `#f0f0f0`
- **Assets**: The official Echoray logo is served via CDN to ensure compatibility and fast loading.

## 4. UI & User Experience

### High-Fidelity OTP Input
The `OTPInput` component (`src/components/ui/otp-input.tsx`) provides a "big-tech" experience:
- **Individual Digit Boxes**: Clear visual separation for the code.
- **Auto-Focus**: Automatically moves to the next box and handles backspace navigation.
- **Auto-Verification**: All auth forms monitor input length and call the API immediately when the 6th digit is entered, removing the need for a final "Submit" click.

### Glassmorphism Theme
Auth forms are integrated into the global design system:
- **Backgrounds**: `backdrop-blur-xl` with subtle `primary/5` shadows.
- **Animations**: `framer-motion` for smooth transitions between signup/verification steps.

---

## 5. Backend Implementation (`convex/`)

- **`auth.ts`**: Configures the `Password` provider and hooks into `ResendOTPVerification` / `ResendOTPPasswordReset`.
- **`ResendOTP.ts`**: The "brain" of the OTP system. Handles code generation, HTML template rendering, and the rate-limiting logic.
- **`schema.ts`**: Defines the `users` table with a mandatory `email` index for fast lookups during authentication.

---

## 6. Development & Maintenance

1. **Changing OTP Expiry**: Modify `maxAge` in `convex/ResendOTP.ts`.
2. **Updating Email Templates**: HTML templates are located directly in the `ResendOTP.ts` file for simplified management.
3. **Throttling Adjustments**: The `recentSends` Map in `ResendOTP.ts` controls the cooldown period.
